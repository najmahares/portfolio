PRAXIS

Simulation-first investing education. Practice decisions without risking real capital.

PRAXIS is a full-stack learning platform for retail investing. It combines a structured 131-lesson curriculum, a virtual portfolio that trades real companies at real prices, and an AI mentor that tracks each learner's progress and adapts to it. The market layer currently targets the Nairobi Securities Exchange. The learning model, the practice engine, the mentor, and the portfolio simulator are market-agnostic and designed to be extended.

Overview

PRAXIS is a practice environment for retail investing. The premise is that judgment in financial markets is built through repeated decision-making under feedback, not through passive content consumption. The product operationalizes that premise into a repeatable loop: read a lesson, work through a practice card, place a simulated trade, review the outcome, and receive structured feedback from an AI mentor.

The platform is a single Next.js application with an authenticated application shell, a curriculum engine, a virtual portfolio simulator, a market data layer, an AI mentor pipeline, a community layer, and an admin console. Data is stored in Supabase Postgres across 17 tables. Session management, rate limiting, audit logging, and the AI pipeline are all custom implementations.

The product scope is deliberately bounded. PRAXIS is not a brokerage, not a research platform, not an advisory service, and not a course marketplace. It is a simulation product with an AI feedback layer and a structured curriculum.

The Problem

Retail investors have no low-cost environment in which to develop judgment before committing capital. The available options each fail in a specific way. Trading simulators assume prior knowledge of market vocabulary and mechanics. Financial literacy content measures recall of definitions rather than quality of decision. Brokerage demo accounts execute trades without consequence, which does not reproduce the emotional and cognitive load of real capital. General-purpose AI assistants answer direct questions like "what should I buy" rather than building the reasoning that leads to an answer.

The gap is not access to information. The gap is access to a feedback loop that connects a decision to its outcome and forces the learner to articulate why the decision was made. PRAXIS is built around that loop.

Architecture

Frontend. Next.js 16 with App Router. React 19 with server and client components. TypeScript in strict mode. Route groups separate the authenticated app shell from public routes and the admin console. Custom design system implemented in CSS modules and inline tokens with light and dark themes.

Backend. Next.js API routes on Node runtime. All routes re-validate input server-side. Authentication uses Supabase Auth for identity and a custom session layer on top: HttpOnly cookies, SHA-256 hashed tokens in a sessions table, revocation support, and a 60-second in-memory verify cache. OAuth uses PKCE with an HttpOnly verifier cookie.

Database. Supabase Postgres, 17 tables covering users, sessions, curriculum progress, portfolio state, market data caches, mentor memory, notifications, bookmarks, community content, admin actions, and platform events. Queries are scoped by user_id at the API layer.

AI layer. Groq API with the openai/gpt-oss-120b model. Streaming via native ReadableStream. A second silent extraction call runs after each assistant reply to persist durable facts about the learner. Retrieval is recency-based. No vector database in the current implementation.

Infrastructure. Upstash Redis for rate limiting. Resend for transactional email (password reset, with a branded HTML template). pg_cron in Supabase for scheduled retention jobs. Cloudflare Workers via OpenNext for deployment.

Engineering Deep Dive

Mentor pipeline. A user message triggers a sequence: authenticate the session, load the last N durable facts about the learner from the mentor_memories table, assemble a system prompt that combines a fixed persona with dynamic context (current route, curriculum progress, holdings), stream a completion from Groq, and then fire a second silent request that extracts durable facts from the turn and persists them. The extraction pass uses JSON mode and a strict schema. Extraction failures are silent; the chat response is not blocked by them.

Message rendering. Assistant responses are parsed by a hand-written markdown renderer that produces React elements directly. No raw HTML injection on assistant output. Supported block types: paragraphs, headings, ordered and unordered lists, fenced code, Mermaid diagrams, and quiz directives. Inline formatting supports bold, italic, and inline code through a tokenizer that outputs React nodes. Diagrams render through Mermaid in strict security mode, with the resulting SVG normalized and sanitized before insertion. Images are proxied through a server route so the browser never holds provider credentials.

Session model. Supabase issues an identity JWT. PRAXIS issues its own session token, hashes it with SHA-256, stores the hash in a sessions table, and sets an HttpOnly cookie with the raw token. Verify is cached in memory for 60 seconds to keep per-request overhead low. Revocation is immediate and invalidates the cache. Multiple concurrent sessions per user are supported and individually revocable.

Event logging. Every authentication attempt, admin action, rate limit hit, and community action writes a row to platform_events with severity (info / warn / critical), IP, user-agent, and a JSON metadata payload. Destructive admin actions additionally write to admin_actions for a permanent audit trail. A daily pg_cron job prunes rows by severity tier: 90 days for info, 365 days for warn, 1095 days for critical. Rows flagged retain_forever are never pruned.

Quality Assurance

Testing is organized in two layers: a Playwright end-to-end suite covering critical user paths, and a static analysis and build gate that runs before every commit.

Playwright e2e suite. Coverage spans three primary flows, each with its own spec file. The auth spec exercises signup, login, session persistence, logout, and protected route redirects. The learning spec exercises the curriculum tree, lesson navigation, progress persistence, and level unlock logic. The portfolio spec exercises setup, trade execution, holdings derivation, and P&L calculations. Tests run headless in CI and in headed or interactive UI mode locally. A dedicated cleanup script removes test users after each run so the suite is idempotent.

Static analysis and build. TypeScript compile with zero errors. ESLint clean. Production build must succeed before merge. Console must be free of errors on every route. Routes must load directly by URL, not only through in-app navigation.

Security and accessibility checks. Server-side re-validation on every mutating endpoint. Authorization check on every user-scoped resource. No secrets present in client bundles. Keyboard navigability on interactive surfaces. Reduced-motion preference respected. Dark mode contrast verified against WCAG AA. Error and empty states implemented on every data surface.
