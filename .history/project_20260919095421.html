Auditerra

Land Restoration Monitoring Platform

Auditerra is a connected land-restoration platform that brings together field experts, smallholder farmers and institutional supervisors through a mobile application and web-based monitoring interface.

View Supervisor Dashboard → View Informational Site

Overview

Auditerra was developed as a multi-interface platform for supporting land-restoration work in the field and monitoring progress at an institutional level.

The solution consists of an independent Flutter mobile application for field experts and a React, Next.js and TypeScript PWA for institutional supervisors.

Field experts can capture geolocation and soil-health data, respond to smallholder farmer tickets and document restoration activities. Supervisors can use the web interface to monitor expert locations, farmer tickets, resolution rates, restoration activity and scheduled 60-day revisits.

The Challenge

Land-restoration work involves people collecting information in the field while other stakeholders need a broader view of what is happening across restoration activities.

Field experts need tools that work around their workflows, while institutional supervisors need structured information to monitor activity, follow up on farmer needs and understand progress.

The challenge was to connect these different workflows into one practical system without losing sight of the people using it.

The Solution

We designed Auditerra around two connected experiences. The field application supports experts while they work with farmers, collect environmental information and document restoration activities.

The supervisor PWA provides an institutional view of field activity, allowing supervisors to monitor expert locations, farmer tickets, resolution rates, restoration activities and follow-up visits.

AI-Powered Soil Assessment

A key part of Auditerra is its soil-assessment workflow. The system combines soil measurements and images with curated Kenyan soil and crop information to provide context-aware assessments.

The Gemini-powered retrieval-augmented generation (RAG) workflow uses this information to generate soil assessments, reports and recommended next actions.

Engineering

The platform combines an independent Flutter mobile application with a React, Next.js and TypeScript progressive web application, supported by backend services and a PostgreSQL database.

The architecture was designed to keep field workflows separate from the institutional monitoring experience while allowing the two interfaces to work with shared application data.

Agreement Risk Scanner

Full-Stack NLP Application for Contract Risk Analysis

Agreement Risk Scanner is a full-stack NLP application that helps everyday users understand the hidden risks buried inside Terms of Service agreements. It was inspired by the reality that most people click "I Agree" without reading the fine print.

View Live App → View API Documentation

Overview

Agreement Risk Scanner was built to solve a problem most people experience but rarely address: legal agreements are long, intentionally dense, and full of language that hides real risk.

The application lets users either paste contract text, upload a PDF or DOCX file, or one-click scan the live terms of platforms like TikTok, YouTube and Instagram.

Once submitted, the agreement is broken down into individual clauses, classified by a Machine Learning model, and returned to the user as a structured report — complete with a risk score, plain-English explanations and a downloadable PDF.

The Challenge

Terms of Service agreements are structured to protect the provider, not the user. The clauses that matter most are written in language designed to be skipped.

A user cannot realistically read a 40-page agreement carefully every time they sign up for a new app. Existing legal tools are built for lawyers, not for the average person.

The challenge was to build a system that could read the agreement automatically, identify the clauses that carry risk, and explain those risks in a way anyone can understand — without requiring a legal background.

My Contribution

This was an end-to-end solo project. I worked across the entire stack — from defining the problem to deploying and securing both the application and the infrastructure that runs it.

Problem Definition Defined the target user, the scope of the risk categories and the boundary between informational output and legal advice.
Machine Learning Built and validated a traditional NLP pipeline using TF-IDF feature extraction and a Linear SVM classifier.
Backend Engineering Developed a FastAPI service with SQLAlchemy, PostgreSQL, authenticated routes and a layered service architecture.
Security Engineering Implemented JWT access and refresh tokens, Argon2 password hashing, rate limiting and account lockout.
Frontend Engineering Built the full user experience in Next.js, including document upload, risk dashboards and PDF report generation.
Quality Assurance Validated authentication, authorization, scan isolation and rate limiting through a layered test suite.

The Solution

The platform is split into two connected systems: a Machine Learning backend that classifies contractual clauses, and a React frontend that turns those classifications into something a non-lawyer can actually use.

Every submitted agreement is broken into individual clauses. Each clause is passed through the ML model and assigned to one of five risk categories. The results are then aggregated into a weighted risk score out of 100, grouped by priority, and displayed with a plain-English explanation.

Users can filter findings by severity, toggle between legal and simplified explanations, read actionable suggestions, and download a professional report of the entire analysis.

Machine Learning Pipeline

The core intelligence of the platform is a traditional NLP classification pipeline. The model was trained on labeled contractual clauses to recognise five categories of risk.

Terminate Contract
Remove Content
Unbalanced Delegation
Other Patterns
Fair / Standard

The pipeline uses TF-IDF (Term Frequency–Inverse Document Frequency) to convert raw clause text into numerical vectors. Those vectors are then classified by a Linear Support Vector Machine.

I deliberately chose a traditional ML approach over an LLM or deep learning model. For a narrow, supervised classification problem like this, TF-IDF + SVM provides high accuracy at a fraction of the computational cost.

Security Engineering

Because the platform handles user accounts, contracts and authentication, security was treated as a first-class concern.

Argon2 Hashing Passwords stored using memory-hard Argon2 hashing resistant to GPU-based brute-force attacks.
JWT Access & Refresh Short-lived access tokens paired with refresh tokens for secure, seamless sessions.
Rate Limiting Authentication endpoints limited to prevent automated brute-force attempts.
Account Lockout Accounts temporarily locked after repeated failed login attempts.
Anti-Enumeration Generic error responses prevent attackers from discovering which emails are registered.
Input Validation Password strength, file type signatures and payload sizes validated before processing.

Engineering

The backend is built with FastAPI and follows a layered architecture separating routing, services, repositories and schemas.

The frontend is built with Next.js using the App Router, with route-level protection, context-based authentication and a component-driven UI. Document parsing for PDF and DOCX files happens entirely client-side.

Both halves are deployed independently — the backend on Render with a PostgreSQL database, and the frontend on Vercel.
